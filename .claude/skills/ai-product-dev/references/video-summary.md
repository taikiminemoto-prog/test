## 1. ソロプレナーとは（2:14〜）

- AIを使って、アプリやWebサービスの事業を1人、またはごく少人数で作る人たち。
- これまでは、VCから資金を集めてチームを作り、時間とお金をかけて作るのが普通だった。今は自己資金で、少人数で速く作り、月に数億〜数十億円を売り上げる例も出ている。
- 経営者が開発からリリースまでをAIで自分でやる。外から資金を集めずに（ブートストラップで）スタートアップ並みのインパクトを出す。ここが従来の会社との大きな違い。
- すでに組織を持つ経営者にも重要。経営者1人で新規事業をどんどん作れるようになる。

## 2. 成功している例（2:54〜）

- Zach Yadegari（Cal AI）: 若い起業家。食事のカロリー計算などができる消費者向けのAIアプリ。今年の売上見込みは約75億円。フィットネス大手の MyFitnessPal への売却が決まり、本人は次にハードウェアのスタートアップを始めている。
- Marc Lou: 各プロダクトの売上をリアルタイムで公開し、過程をすべて見せる。それでついたファンがそのまま利用者になり、年に数億円規模を売り上げる。打席の数で勝負するやり方。
- 体感では、半分近くが非エンジニア。
- 表に出るかどうか: 発信力で利用者を集められる利点がある一方、1人で作れるものは大企業が資本ですぐ追いつける。追いつかれない所までは伏せておく人もいる。
- ゲスト自身は、本業をしながら2か月で2つのプロダクトを出した。専念すれば、月に1つは確実に出せる感覚。

## 3. YouTuber と重なる4つの構造（6:58〜）

過去10年、個人の影響力や創造性でお金を稼ぐ代表は YouTuber だった。ソロプレナーは、ほぼ同じ構図になっている。

1. **作るハードルの崩壊**: 動画が「高価な機材と編集技術」から「スマホ1台」になったのと同じく、ソフトウェアも「コードを書く技術」から「AIエージェントに作りたいものをきちんと伝えれば誰でも作れる」になった。プログラミングができるほうが有利なのは変わらないが、デザインや企画が得意な人が今むしろ輝いている（テレビ出身でも YouTube で成功する人としない人がいるのと同じ）。
2. **注目（アテンション）がお金になる**: SNSでの注目が、そのまま売上に直結する。作るのが簡単になった分、作った後に「届ける」ことの比重が大きくなり、本人の発信力が強い武器になる。マーケティングが得意な人は有利（ゲストも、サービスを伸ばす仕事の経験が大いに生きている）。
3. **大手が入らない所で高い利益を上げる。**
4. **最初は侮られるが、圧倒的な試行回数で大きなインパクトを出す**: 個人が作るものは「質が出ないだろう」と見られがちだが、YouTuber と同じく、試行の数で気づけば独自の大きなインパクトを出している。

これからのソフトウェア開発を占うには、YouTube の市場がどう発展したかを見るとよい。

## 4. 経営者が自分で作る3つのメリット（10:35〜）

1. **試行回数（打席の数）を圧倒的に増やせる**: いいアイデアを思いついても、エンジニアに頼まないと進まないと、どこかで止めてしまったり、実験が速く回らなかったりする。自分の空き時間だけで作って出せる。伝えるときの行き違いもない。
2. **課題をいちばん深く分かっている本人が作るので、いいものができやすい**: こだわれるだけこだわれる。人に頼むと、やりたいことが100あっても相手の負担を考えて80で止めがちだが、自分で作るなら100作れる。
3. **世の中の不満（プロダクトの種）を見つけやすくなる**: 自分で作っていると、「これはプロダクトの種だ」と気づけるようになる。

ソロプレナーを目指さなくても、作れるようになったほうがいい。

## 5. ゲストが1人で作ったもの（12:49〜）

- 本業と並行して、2か月で2つ（Web と iOS アプリ）をきちんとローンチした。
- 1つ目は、理想の情報収集（インプット）サービス。記事や動画を保存すると、AIが読んで要約し、それを読んだり、移動中に音声で聞いたりできる。学んだ内容は、Claude Code や Codex の知識としてリアルタイムに同期される。ブラウザの拡張機能、iPhone アプリ、メールの転送、Web 版、AIエージェントとつなぐためのコマンドラインの仕組みまで作った。
- 2つ目は、食事のパーソナルトレーナー（栄養管理のAIトレーナー）。AIチャットのサービス。
- 決済（Stripe、iOS のアプリ内課金）、LP、ストアに出すための画像素材、紹介動画まで、すべて1人とAIで作った。
- 2〜3人で作るより、1人のほうが速いこともある。人を介して指示を出すより、AIに直接渡すほうが認識のずれが少ない。フィードバックはAIがくれるし、人の反応は周りの起業家や友人に使ってもらって得ればよい。

## 6. 最初のセットアップ（16:18〜）

多くの人がつまずくのは最初のセットアップ。ここを越えれば、あとは Claude Code や Codex が頼んだことをだいたいやってくれる。やることは3つだけ。

1. Claude Code か Codex を入れる（今の2強。自分に合うほうでよい）。
2. 空のフォルダを1つ作って開く。そのフォルダが、AIエージェントの仕事場になる。
3. 日本語で最初の指示を出す。どんなユーザーのどんな課題を解決したいか、できるようになりたいこと、こだわりたいこと、避けたいこと。音声入力で、部下に伝えるように一気に話せばよい。

まずは、前から自分が困っていることを1つ作ってみると、「こうやって作れるのか」と実感できる。

## 7. 完成までの11ステップ（18:40〜）

この順番で進め、各ステップのポイントを押さえれば、リリースできる品質のものが作れる。

1. **コンセプト設計（18:40〜）**: 何を作るかは人が決める。誰のどんな課題をどう解決するか、入れたい機能を文章にしてAIに渡す。シンプルだからこそいちばん難しい。裏でAIが動くサービスは原価がかかり、完全無料は無理。だから「既存のAIツールでは絶妙に不便」かつ「すでにお金を払っている」領域を狙う（例: 情報収集なら、リサーチの外注や書籍、タクシー代で時間を買っている／食事管理なら、パーソナルトレーナーや医療ダイエット）。お金を払っていない領域だと「便利だね」で終わり、財布が開かない。
2. **仕様設計（22:11〜）**: UXの5レイヤー（Garrett）を使う。戦略 → 要件 → 構造 → 骨格 → 表層を下から積み、上の層は下の層と矛盾させない。仕様設計は下の3層。AIはこの枠組みを知っているので、「戦略レイヤーの粒度のドキュメントを作って」と頼み、それを前提に次の層を作る、と入れ子で進める。ゲストも手では書いていない。
3. **画面設計（25:46〜）**: 主な画面のワイヤーフレームを作らせ、主な画面は数パターン出させて、選ぶだけ。センスの伝え方は言葉と見本の2つ。言葉なら「FWA、Webby Awards、Awwwards などの賞を取れる水準まで自分で磨いて」と頼む。曖昧な「かっこよく」だとAIはほどほどで止まるが、賞という基準があれば「まだ足りない」を自分で判断できる。
4. **プロトタイプ実装（28:00〜）**: デザインを作り込む前に、一通り動くものを作る。3つの文書とワイヤーフレームを渡して、一気に作らせる。ポイントは、Webを必ず先に作ること。スマホアプリは、ビルドと実機での確認の往復が重い。Webで確かめてからネイティブに翻訳させる（AIは翻訳が得意なので、Webの分は無駄にならない）。
5. **価値検証（29:45〜）**: コアユーザーが毎日使う・使いたくなるか。使ってもらい、「なくなったらどのくらい困るか」を5段階で聞き、「非常に困る」が過半数ならいける。
6. **本番実装（30:17〜）**: 実装したAIとは別のAIに、厳しくレビューとテストをさせる（Claude Code が作り、Codex が見る）。Claude Code の中でも、Fable が計画と管理をし、Opus や Sonnet がサブエージェントとして並列に実装する。決済も、テスト用のカード番号を使ってAIに通させる。根深いバグは「根本原因を分析して、根本的な解決方法を分かりやすく提案して。まだ実装はしないで」の趣旨で頼み、人が理解して方針を選ぶ。AIチャットは操作が無限にあるので、テストシナリオ表を作って全部AIに実行させる。
7. **価格設計（34:28〜）**: 広告では成り立ちにくいので課金する。ライト・ミドル・ヘビーを2：6：2と置いてコストと売上をシミュレーションし、目標の利益率になるプランを出させる。作り手の感覚と、ベータ利用者への4つの質問による価格アンケートでダブルチェックする。ここまで来れば、サービスとしていける感覚になる。
8. **デザイン（35:35〜）**: そのまま頼むと「AIっぽい」見た目になる。参考を1つだけ渡すと真似になるので、ムードボード（複数のインスピレーション）を渡す。いきなり画面を作らず、先にデザインシステム（色や部品のルール）を作らせ、そこで違和感を直す。微妙な仕様案やデザイン案は文字で判断せず、判断用のWebサイトや使い捨てのHTMLを作らせて、見て選ぶ（例: 登録時の文言の案を並べ、チェックしたものだけが実装される専用のページ）。ゲストは Figma を使わず、AIだけでデザインした。
9. **セキュリティ（39:06〜）**: 理想は、シニアのセキュリティエンジニアのレビュー。まず必ずできるのは、AIに攻撃者として一通り攻撃させ、通ったところを全部直すこと（ペネトレーションテスト）。
10. **マーケティング素材（39:47〜）**: 「作って」で作れる。紹介動画は、HyperFrames のような、AIに動画を作らせる枠組みを使う。こだわる所（声など）は人に予算を割き、ほかはAIで、という配分がしやすい。
11. **計測（41:53〜）**: Google アナリティクスや Amplitude の導入も、タグとイベントの設計から一式やってもらえる。あとは、データを見ながら改善のサイクルを回す。

## 9. 締めくくり（43:32〜）

- 任せられたことと、自分にしかできなかったことの線は、はっきりあった。何を作るか（コンセプト）、価値があるかの判断、価格の決定、重要な仕様の分かれ道の決定は、自分にしかできなかった。そこは自分がしっかりやる、という意識が大事。
- 「AIを使えば誰でもサービスを作れる」は半分本当で、半分うそ。これを作りたいという強い意思と、やり切る力がないと、途中で飽きてしまう。逆に、それがある人には、今は強力な武器がある。
- 日本ではまだやっている人が少なく、今からでも十分に間に合う。特に学生や若手に勧めたい。最初の簡単な仕事が自動化され、キャリアのはしごが外れていると言われるが、自分がオーナーとして何かを作る経験を一足飛びに積める。
- ゲストは今後、自分の思想や作りたい世界観を詰め込んだものを作るつもり。
