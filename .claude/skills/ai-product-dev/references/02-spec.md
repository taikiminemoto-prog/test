# ステップ2: 仕様設計（UXの5レイヤーの下3層）

「仕様設計」と言われても、作ったことがなければ何を決めればいいか分からない。そこで、UXデザインの教科書の最初に載っている枠組み、**UXの5レイヤー**（Jesse James Garrett『The Elements of User Experience』）を使う。

| 層 | 決めること | どのステップで |
|---|---|---|
| 5. 表層 Surface | 見た目（色、文字、質感） | ステップ8 |
| 4. 骨格 Skeleton | 画面の配置 | ステップ3 |
| 3. 構造 Structure | 情報の構造、ユーザーの利用の流れ | **このステップ** |
| 2. 要件 Scope | 入れる機能とコンテンツ | **このステップ** |
| 1. 戦略 Strategy | ユーザーのニーズ、プロダクトの目的 | **このステップ** |

ビルと同じで、下の層から順に決め、上の層は下の層と矛盾させない。全部を一度に考えようとすると、何から考えればいいか分からなくなる。

AIはこの枠組みをよく知っているので、ユーザーが手で書く必要はない（動画のゲストも手では書いていない）。前の文書を前提に次の層の文書を作る、を順番に繰り返す。

## 進め方

1. 01-concept.md を前提に、「ギャレットのUXの5レイヤーの、戦略レイヤーの粒度」で 02-strategy.md を作る。
2. 02-strategy.md を前提に、要件（スコープ）レイヤーの仕様書 02-scope.md を作る。
3. 02-scope.md を前提に、構造レイヤーの仕様書 02-structure.md を作る。

文書を1つ作るたびに、要点（3〜5行）と、ユーザーが決めるべき点だけを見せて確認する。全文を読ませる必要はない。

## 02-strategy.md（戦略）

- ターゲットユーザー: 誰か、どんな状況か、今は何で代用しているか
- ユーザーのニーズ: 解決したい課題、達成したいこと
- 提供する価値: なぜ他の手段ではなくこれを選ぶのか
- プロダクトの目的: 事業として何を達成するか、成功をどう測るか
- やらないこと

## 02-scope.md（要件）

- 機能を優先度の順に（必須 / あるとよい / 将来 / やらない）。各機能に「ユーザーが何をできるか」と「戦略のどのニーズに効くか」を書く。どのニーズにも効かない機能は入れない（下の層と矛盾しているため）。
- コンテンツ（文章、データ、通知など）
- 品質の条件（速さ、対応する端末、AIの原価の上限、個人情報の扱い）
- 最初に出す範囲（MVP）。集中して数週間で出せる大きさにする。

## 02-structure.md（構造）

- 情報の構造: 扱うもの（例: 利用者、記事、メモ）とその関係、画面の一覧と階層
- 主な利用の流れを手順で: 初めて来て最初に価値を感じるまで / 毎日の使い方 / 課金
- 例外の流れ: データが空のとき、失敗したとき、通信が切れたとき、AIの応答が遅い・失敗したとき

利用の流れを整理しないと、体験がちぐはぐなプロダクトになる。

## ユーザーが決めること

最初に出す範囲（どの機能をMVPに入れるか）と、仕様の重要な分かれ道。微妙な案を比べるときは判断用ページを使う。

## 完了の条件

- 3つの文書が揃っている。
- 要件のすべての機能が、戦略のどれかのニーズにつながっている。
- 構造の流れが、要件の必須機能をすべて通っている。
- 最初に出す範囲をユーザーが決めた。
