# ステップ7: 価格設計

裏でAIが動くサービスは広告では成り立ちにくく、利用者に課金してもらうのが前提になる。価格はいちばん重要な意思決定の1つで、決めるのはユーザー。Claudeは、コストと利益のシミュレーションと、判断の根拠を用意する。

## 1. コストと利益をシミュレーションする

- 利用者の分布を **ライト：ミドル：ヘビー ＝ 2：6：2** と置く。多くのサービスが、だいたいこう分布する。
- 層ごとの月の利用量（AIを呼び出す回数、使う量）を仮定し、1人あたりのAIの原価を出す。AIの料金は記憶で書かず、使うサービスの公式の料金ページで確かめ、確かめた日付を書く。
- 忘れがちな費用も入れる（補足）: サーバーやデータベースなどの固定費、決済手数料、アプリストアの手数料（条件で率が変わるので最新の規約で確認）、無料で使う人のコスト。
- 「利益率が◯％になるプランを考えて」の形でプラン表を作る。中身は、無料枠の有無と上限、各プランの価格と含まれる量、層ごとの粗利。
- ヘビー層で赤字にならないかを必ず確かめる。赤字になるなら、上限、従量課金、使い方のルールなどで手当てする。
- 前提の数字には、出典か「仮定」と書く。計算は小さなスクリプトで行い、数字の取り違えを防ぐ。

## 2. 2つの方法で確かめる

- **作り手の感覚**: 提案がしっくり来るかを、ユーザーに聞く。
- **ベータ利用者への価格アンケート**: 4つの聞き方で、価格の最適な交点を見つける方法（PSM分析、Van Westendorp 法）。

```
Q1. いくらだと「安すぎて、品質が不安になる」と感じますか？
Q2. いくらだと「安い（お得だ）」と感じますか？
Q3. いくらだと「高い」と感じ始めますか？（買うかどうかは考える）
Q4. いくらだと「高すぎて、買わない」と感じますか？
```

回答はCSVにまとめる（1行目の見出しは `too_cheap,cheap,expensive,too_expensive` か `安すぎる,安い,高い,高すぎる`）。このスキルのフォルダにある `scripts/psm.py` で集計する。

```bash
python3 <このスキルのフォルダ>/scripts/psm.py answers.csv
```

下限、理想価格、妥協価格、上限が出る。シミュレーションで出た「必要な価格」と、アンケートの「受け入れられる範囲（下限〜上限）」を並べ、重なる所を推奨する。重ならなければ、原価を下げる案（安いモデルとの使い分け、結果の再利用、上限の設定）か、対象者を変える案を出す。

## 3. 決めてもらう

推奨のプラン表、その根拠、別の案を出して、ユーザーに決めてもらう。決まった内容は 07-pricing.md と PROGRESS.md に記録する。動画のゲストは、ここまで来ると「サービスとしていける」という感覚になったと言っている。

## 成果物: docs/product/07-pricing.md

- 前提（料金を確かめた日付、各層の利用量、手数料）
- 層ごとのコストと粗利の表
- プラン表（推奨と別案）
- アンケートの結果（人数、下限・理想・妥協・上限）
- ユーザーが決めた価格と、その理由

## 完了の条件

- ユーザーがプランと価格を決めた。
- ヘビー層を含め、どの層でも粗利がマイナスにならない。なる場合は、その手当てがある。
