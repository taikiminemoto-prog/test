# ステップ8: デザインの作り込み（表層）

普通にAIに頼むと、いかにも「AIが作った」見た目になる。避け方は次の4つ。動画のゲストは、デザインツール（Figma）を使わずAIだけでデザインを作り、こだわって何度も直している。

## 1. ムードボードを作って渡す

参考のデザインを1つだけ渡すと、それの真似になる。いくつかのインスピレーションを集めたボード（ムードボード）にして渡す。

- ユーザーに、好きなサイト、アプリ、画像を3〜8個集めてもらう（URLやスクリーンショット）。それぞれ何が好きか（色、余白、文字、動き）を一言ずつ添えてもらう。
- 集めるのが難しければ、Claudeが方向性の違う候補を判断用ページに並べ、選んでもらう。
- `docs/product/08-moodboard/` に置き、共通する要素（雰囲気、色の傾向、文字、情報の密度、角の丸み、動き）を言葉にする。

## 2. 画面より先に、デザインのルール（デザインシステム）を作る

いきなり画面をデザインさせない。ムードボードから、先にルールを作らせる。

- 色: 役割ごとの色（背景、面、文字、補助の文字、強調、成功、注意、エラー）を、明るい表示と暗い表示の両方で
- 文字: 書体、大きさの段階、行間
- 余白の段階、角の丸み、影、アイコン
- 部品とその状態: ボタン、入力欄、カード、一覧、ナビゲーション、ダイアログ、空のとき、エラーのとき（通常 / 押したとき / 使えないとき / 読み込み中）

これを1枚の見本ページ（`docs/product/08-design-system.html`）にしてユーザーに見せ、違和感があればこの段階で直す。ここが固まれば、以降の画面がぶれなくなる。確定したら、コードの中の共通の設定（CSS変数やテーマ）として実装し、全画面がそこだけを参照するようにする。

## 3. 外の物差しで磨く

「Awwwards・FWA・Webby Awards を取れる水準」を物差しにして、画面ごとに自分で見直して磨く。画面のスクリーンショットを撮り、自分の目で確かめる。どこで止めるかはユーザーが決める。

## 4. 微妙な案は、見て決めてもらう

デザイン案、文言、微妙な仕様の案は、チャットの文章では判断しにくい。判断用ページ（`assets/decision-page.html`）か使い捨てのHTMLで案を出し、ユーザーは選ぶだけにする。

- 例: 登録画面の文言の案を並べ、チェックを付けたものだけを採用して実装する。
- 例: 新しいデザイン案は「使い捨てのHTMLで提案」として、見た目で比べられる形で出す。

## 完了の条件

- デザインシステムをユーザーが確認し、コードに実装され、全画面がそれを使っている。
- 主な画面が物差しでの見直しを通り、ユーザーがよいと言った。
